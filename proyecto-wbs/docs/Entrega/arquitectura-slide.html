Arquitectura Técnica de Software

4.4.9 ARQUITECTURA TÉCNICA
🏛️ Principios Arquitectónicos
1
Rol Único (`USER`)
Entidad transversal: una misma persona enseña y aprende sin dualidad de tablas.
2
Transacciones Atómicas (Freeze)
Custodia temporal de créditos con reversión automática ante cancelación.
3
Arquitectura en 4 Capas
Separación estricta: Routers → Services → Repositories → Models.
4
API First (Contratos JSON)
Especificación OpenAPI / Swagger tipada con Pydantic y JWT Bearer tokens.
💾 Persistencia Dual Transparente

El motor SQLModel se adapta automáticamente al entorno mediante la variable DATABASE_URL:

SQLite Local
local_dev.db rápido, multihilo, sin dependencias externas.
PostgreSQL Cloud
Instancia administrada en Render / Supabase para producción.
🌐 Frontend Web Client (SPA Desktop) Vue.js / Tailwind CSS / Vanilla JS
Catálogo & Filtros Buscador ILIKE, badges
Dashboard de Usuario Balance, clases, reputación
Modal de Reserva Selector fecha/hora, Meet
Cliente HTTP Fetch API + Bearer JWT
↓ Petición HTTP / JSON (Headers + JWT Bearer) ↓
1. Capa de Routers / Controladores FastAPI (app/routers/)
auth_router /api/v1/auth
users_router /api/v1/users
publications_router /api/v1/publications
sessions_router /api/v1/sessions
↓ Invocación de casos de uso y DTOs de entrada ↓
2. Capa de Servicios / Lógica de Negocio Pydantic & Domain (app/services/)
AuthService Bcrypt, generación JWT
CreditService Custodia (freeze), débito
MatchingService Cruce recíproco A ↔ B
SessionService Agenda y validación horario
↓ Consultas transaccionales y aislamiento de persistencia ↓
3. Capa de Repositorios / Acceso a Datos SQLModel Session (app/repositories/)
UserRepository Query usuario, balance
PubRepository Filtros SQL dinámicos
SessionRepository Bloqueos de franjas
ReviewRepository Agregación de rating
↓ Mapeo Objeto-Relacional (ORM) ↓
4. Capa de Modelos de Datos & Entidades SQLModel Entities (app/models/)
User id, email, password_hash
Publication type, title, category, level
Session status: P/A/C/X, escrow
Review rating 1-5, comment
