# Registro de cambios de la especificación

| Fecha | Cambio | Impacto | Estado |
|---|---|---|---|
| 2026-09-25 | Se consolidó el documento como especificación del MVP. | Reorganización de la documentación. | Aprobado |
| 2026-09-25 | Se incorporó inicialmente la distinción entre Docente y Alumno como conceptos centrales. | Afectaba perfiles, propuestas, solicitudes e intercambios. | Reemplazado por rol técnico único `USER` el 2026-10-02 |
| 2026-10-02 | Se adoptó `USER` como rol técnico único; enseñar y aprender son participaciones determinadas por cada actividad. | Afecta perfiles, propuestas, solicitudes, sesiones, créditos y documentación derivada. | Aprobado |
| 2026-10-03 | Se creó el MVP V2 refinado, conservando el MVP anterior como MVP V1. | Introduce una alternativa de fuente de verdad centrada en enseñar, aprender y concretar intercambios. | Pendiente de selección de versión activa |
| 2026-10-03 | Se consolidó el MVP V3 con acceso `GUEST` de solo lectura y agendas públicas por fecha y hora, sin recurrencias. | Afecta acceso público, permisos, visibilidad, disponibilidad, reservas y derivación de API. | Pendiente de aprobación |
| 2026-10-03 | Se adoptó el MVP V3 como fuente de verdad activa. | La próxima derivación debe regenerar WBS, USM, backlog, subtareas, modelo de dominio, API y Jira a partir de V3. | Aprobado |
| 2026-09-25 | Se incorporaron clases grupales, equipos docentes e intercambios equivalentes. | Afecta créditos, reservas e historial. | Reemplazado por alcance futuro |
| 2026-09-25 | Se trasladaron las clases grupales, equipos docentes e intercambios no 1 a 1 al alcance futuro. | El MVP queda limitado a sesiones individuales. | Aprobado |
| 2026-09-27 | Se eliminaron ejemplos técnicos y directorios vacíos que ya no forman parte de la estructura vigente. | Se actualiza la estructura documental; no cambia el alcance del MVP. | Aprobado |
| 2026-09-27 | Se actualizaron la WBS y el User Story Map, y se creó el backlog a partir del MVP aprobado. | Se agregan tres documentos derivados trazables y se explicitan pendientes y exclusiones. | Aprobado |
| 2026-09-27 | Se creó la skill `crear-epicas` para derivar y mantener épicas trazables desde el MVP. | Facilita la organización del backlog y una futura preparación para Jira sin agregar alcance. | Aprobado |

Los cambios futuros deben registrar qué parte del MVP modifican y qué documentos derivados requieren revisión.
