# Directriz conceptual del User Story Map

La captura de referencia se utiliza para identificar los conceptos y la relación entre los niveles del User Story Map. No define colores, tipografías, distribución visual ni una herramienta específica.

El ejemplo muestra un rol, actividades agrupadas, tareas del usuario y detalles. Esta relación conceptual debe tomarse como referencia, no el cuadro, los colores ni el contenido del ejemplo.

## Componentes

### Backbone

Es la estructura superior del mapa. Está formada por las actividades principales que representan el recorrido general del usuario.

### Activities

Son los grandes momentos o etapas de interacción con el producto. Deben poder leerse como una secuencia narrativa.

### Narrative flow

Es el orden en que el usuario atraviesa las actividades. El mapa debe contar una historia de uso de izquierda a derecha.

### User tasks

Son las acciones que el usuario necesita realizar dentro de una actividad. Deben estar expresadas desde la perspectiva del usuario y no como tareas técnicas del equipo.

### Details

Son historias o necesidades más específicas que descomponen una tarea. Deben ser suficientemente concretas para describir valor y poder validarse.

### Release slice

Es un corte horizontal del mapa que reúne las historias necesarias para una versión del producto. El primer corte representa el MVP; los cortes posteriores representan ampliaciones.

## Organización conceptual

El mapa debe identificar el rol, las actividades, las tareas del usuario y los detalles o historias. El flujo debe leerse de izquierda a derecha cuando el formato elegido lo permita, y el release slice debe indicar qué elementos forman parte del MVP.

## Aplicación al proyecto

El mapa debe contemplar los recorridos de Docente y Alumno. Como una persona puede cumplir ambos roles, algunas actividades pueden ser compartidas y otras pueden mostrar acciones específicas para cada rol.

Para el MVP actual, el flujo debe concentrarse en sesiones individuales 1 a 1. No agregar clases grupales, equipos docentes ni intercambios no 1 a 1 al release slice. Solo desarrollar cortes posteriores si el MVP vigente describe explícitamente esas ampliaciones.
